# Languages

The map's own words (buttons, panels, tooltips, messages, the tour and the glossary) come from a language table, so a map can be shown in another language than English. The names and descriptions of your code are written by Claude or Codex, and with a language set they write those in it too.

Available: `en` (English, the default) and `de` (German).

## Choosing a language

- **For good:** add `"lang": "de"` to `floorplan/architecture.json`. Every build and refresh keeps it. Asking Claude or Codex for "the floorplan in German" does this for you.
- **For one build:** `node <skill folder>/scripts/build.mjs <root> --lang de`.
- **Neither:** English, exactly as before.

With a language set, the map's server asks the agent to answer questions, build requested flows and change blueprints in it, and the skill's worksheets (`describe.mjs`, `recent.mjs`) ask it to write names, descriptions, the tour and recent work in it.

## How it works

- `skills/floorplan/assets/lang/<code>.json` is one flat object: key → text. `en.json` is the source; every other table has exactly the same keys.
- `{placeholders}` are filled in when the text is shown: `"count.file.other": "{n} files"`. A translation keeps every placeholder of the English text.
- Counted texts have one key per plural form the language has: `.one` and `.other`, plus `.few` or `.many` where its [plural rules](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) use them.
- A few texts carry a little markup (`<b>`, `<code>`, `<strong>`, `<br>`). A translation keeps the same tags.
- The glossary is in the table too: `glossary.<id>.term` (the name shown; put the English word in brackets when the code uses it, like `Endpunkt (endpoint)`), `.text` (one plain sentence) and `.match` (the words to underline, separated by `|`; a leading `=` matches case exactly, so "REST" doesn't fire on "the rest"). List the words people write in that language, plus the English ones they borrow.
- Numbers and dates: `format.thousands`, `format.decimal` and `format.percent`; the date on an exported copy uses the map's language (an English map keeps the browser's own format).
- `MAP.md`, the map as text for AI workers, is made from the same table by `scripts/lib/mapmd.mjs`: its headings and labels are the `map.*` keys and a few keys the viewer shares, and its content is in the language the map has. The markers above its sections (`<!-- floorplan:parts -->` and so on) are the same in every language, so a program finds a section without knowing which one it is.
- `build.mjs` fills the `{{t:key}}` markers in `viewer.html`'s markup, sets `<html lang>`, and puts only the chosen table into the page (with English for any key it lacks), so the map stays one self-contained file. Scripts call `t(key, vars)` and `tn(key, n, vars)`; extensions in `assets/ui/` get them from `window.Floorplan`, with `lang` and `keys(prefix)`. The build has the same two from `translator(words, lang)` in `scripts/lib/lang.mjs`, for everything it writes that people read: `MAP.md`, the Health findings, a cron in words.

## Translating the findings

The Health check (`scripts/lib/health.mjs`, with `layers.mjs` for Publishability) and the design review of a blueprint (`scripts/lib/blueprint.mjs`) write their findings in the map's language too. Each finding has a fixed `id`, `<check>` or `<check>:<instance>` (`large-files`, `secret:src/config.py`, `publish:private-word:system`), and its words come from the table under `health.<check>.`:

- `health.<check>.title` and `health.<check>.detail` are the title and the explanation. A text that depends on a count has the plural forms instead, `health.<check>.title.one` and `.other`, picked by `tn()` like everywhere else; a text with a few fixed variants has one key per variant (`health.cors.title.credentials` and `.plain`, `health.firebase-rules.writes.title.files` and `.data`).
- The notes on the map's cards are keys of their own (`health.large-files.unread`, `health.single-writer.note.writes`), and so are the pieces several findings share: `health.at` ("line {n}: {what}"), `health.and` ("{a} and {b}"), `health.note.noLogin`.
- Placeholders carry what comes from the code or the map and is never translated: `{file}`, `{name}`, `{table}`, `{n}`, `{date}`, `{where}`. A file name, a host, a table or a key's first characters stay as they are; a number and a date are written as the language does (`1,200` and `March 1, 2027` in English, `1.200` and `1. März 2027` in German). Nothing a finding shows is ever a secret's value: a placeholder gets a kind, a length, a first letter.
- The scan records no words, only keys, so one scan serves a map in any language: the kind of a secret (`health.secret.kind.<kind>`, "a Stripe live secret key"), the form a CORS setting was written in (`health.cors.how.<how>`) and what a Publishability finder found (`health.publish.what.<kind>.one`/`.other`, "a UUID-style id", "2 UUID-style ids") are put into words at build time.
- `fix`, the request to paste into Claude Code or Codex, is a prompt and stays English, built from the English table; so does `change` on a blueprint's review.

Adding a finding means adding its keys to `en.json` and every other table and writing the finding with `t()`/`tn()`; `tests/i18n.test.mjs` fails on a title, explanation or note written straight into the code, on a scan finding that records words, and on a key that is missing or unused.

## Adding a language

1. Copy `en.json` to `<code>.json` (a language code like `fr` or `pt-BR`) and translate every value. Keep the keys, placeholders and tags.
2. Set `lang.name` (the language's own name, shown in the build output) and `lang.englishName` (its English name, used in the instructions for the agent).
3. Add the code to the `lang` row in `skills/floorplan/references/schema.md` and to the list above.
4. Run `npm test`. `tests/i18n.test.mjs` checks that the new table has the same keys, placeholders and markup as English.
5. Build a map with `--lang <code>` and look through it: the header, a panel, a tooltip, the tour and the Health list, and the top of `floorplan/MAP.md`.

To add a word to the map, add its key to `en.json` and every other table, and show it with `t('your.key')`. The test fails when visible text is written straight into `viewer.html` or `assets/ui/*.js`, or when a key is missing or unused.

## Still in English

The fix requests of the Health and design-review findings (prompts for the agent), the report of a false alarm that **Not a problem** can open for the Floorplan developer (a GitHub issue whose labels stay English; the finding's title in it is the map's, as the preview shows), names made up for files nobody has described yet, messages from the map's server (`serve.mjs`), and the scripts' output for the agent (which lists the findings' titles as the map has them).
